# 俯视角赛车 H5 游戏设计规格

## 1. 目标

创建一个独立的、可在桌面浏览器和移动浏览器运行的 Canvas 2D 俯视角赛车小游戏，用于快速验证赛车选择、躲避障碍和持续竞速的核心体验。首版不接入账号、后端、支付、广告或在线排行榜。

成功标准：玩家可以从首页进入选车，选择赛车后开始比赛，使用键盘、鼠标或触摸操作完成一局，看到得分结算，并能通过本地存储保留最高分、金币和车辆解锁状态。

## 2. 用户流程

首页 → 选择赛车 → 比赛 → 结算 → 重新开始或返回选车。

首页提供开始游戏和最高分入口。选车页展示 4 款原创赛车及速度、操控、加速度属性。比赛页持续滚动赛道，生成普通车辆、路障、金币和氮气；玩家横向移动，碰撞会减速，连续撞击或生命值归零后结束。结算页展示行驶距离、金币、最高分和再次挑战按钮。

## 3. 核心玩法

- 玩家赛车位于屏幕下方区域，主要进行横向移动。
- 赛道以固定速度向下滚动，速度随行驶距离逐渐提升。
- 障碍物和 AI 车辆按难度曲线生成，避免在玩家当前位置直接生成不可躲避的碰撞。
- 金币用于本地累计；氮气道具用于短时间加速并获得额外分数。
- 撞击造成减速和视觉反馈；在保护状态或短暂无敌时间内不会重复扣除。
- 得分由行驶距离、收集金币、使用氮气和无碰撞时间共同构成。

## 4. 输入与适配

- 桌面键盘：方向键或 A/D 控制左右移动，空格触发氮气。
- 鼠标：在 Canvas 内拖动控制赛车横向位置。
- 移动端：触摸拖动控制横向位置，界面提供氮气按钮。
- Canvas 使用设备像素比适配，CSS 尺寸以视口为准；限制赛车横向活动范围，避免越界。
- 页面支持竖屏优先，同时在桌面宽屏下保持居中的游戏区域。

## 5. 技术架构

采用独立 Vite + TypeScript 项目。`requestAnimationFrame` 驱动固定逻辑步进与渲染；游戏对象通过轻量实体模型管理，碰撞采用轴对齐矩形检测。Canvas 负责赛道、赛车、道具、障碍物、粒子和速度线；HTML/CSS 负责菜单、选车卡片、HUD、按钮和结算面板。

建议模块：

- `src/game/`：游戏循环、状态机、碰撞、生成器、实体和渲染器
- `src/screens/`：首页、选车和结算界面
- `src/data/`：车辆配置、难度配置和本地存储键名
- `src/styles/`：主题、响应式布局和动效
- `src/main.ts`：应用启动和屏幕切换

## 6. 数据与持久化

车辆先使用原创名称和程序绘制外观，避免首版依赖真实汽车品牌素材。车辆配置包含 id、名称、颜色、速度、操控、加速度、解锁条件。`localStorage` 保存最高分、金币和已解锁车辆。读取异常或数据格式无效时回退到默认状态，不阻断游戏启动。

## 7. 错误与边界处理

- 浏览器不支持 Canvas 时显示可理解的降级提示。
- 页面失去焦点或切到后台时自动暂停，恢复后由玩家主动继续。
- 游戏循环、输入和资源初始化失败时停止当前局并显示重新开始入口。
- 生成器保证障碍物之间存在可行驶通道；难度提升设置上限，避免无限加速导致不可玩。
- 本地存储不可用时仍可游玩，仅不保存进度。

## 8. 验证范围

- 桌面浏览器：Chrome、Edge、Safari，验证键盘和鼠标操作。
- 移动浏览器：验证触摸、竖屏布局和氮气按钮。
- 工程验证：类型检查、生产构建、差异检查。
- 人工验收：完整走通首页、选车、比赛、暂停、结算、重新开始和本地进度保存。

## 9. 首版不包含

真实品牌车型、联网排行榜、账号系统、广告、支付、多人联机、复杂 3D 效果和后台管理。真实品牌车辆只作为未来经过授权后的替换素材方向记录，不进入首版实现。
