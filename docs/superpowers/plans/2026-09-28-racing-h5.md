# Racing H5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a standalone Canvas 2D top-down racing H5 game playable on desktop and mobile browsers.

**Architecture:** A Vite + TypeScript app separates screen UI from a Canvas game engine. A small state machine coordinates home, car selection, race, pause, and result screens; localStorage persists best score, coins, and unlocked cars.

**Tech Stack:** Vite, TypeScript, Canvas 2D API, HTML/CSS, browser localStorage. No gameplay framework or backend.

**Spec:** `docs/superpowers/specs/2026-09-28-racing-h5-design.md`

## Global Constraints

- The first release is a standalone browser game with no account, backend, ads, payments, or online leaderboard.
- Use four original car names and programmatic visuals; do not ship Tesla trademarks or copied vehicle artwork.
- Support keyboard, mouse, and touch input, with portrait-first responsive layout.
- Preserve playability when localStorage is unavailable or contains invalid data.
- Pause when the page loses focus; resume only through an explicit player action.

## Review Focus

- A narrow mobile viewport must keep the Canvas and touch controls usable without horizontal overflow; cover in the responsive shell task.
- A tab switch or hidden page must not advance the race silently; cover in the game lifecycle task.
- Invalid or unavailable localStorage must fall back to defaults without blocking startup; cover in the persistence task.
- Obstacle generation must leave a reachable lane and avoid unavoidable spawn collisions; cover in the generator task.
- Repeated collision frames must not drain all health instantly; cover in the collision task.
